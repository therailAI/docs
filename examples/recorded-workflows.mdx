These are recorded reference journeys, not live customer integrations. Each linked workflow includes its environment, evidence bundle, supplied verifier report, and limitations.

| Workflow | What to inspect | Important limit |
| --- | --- | --- |
| [Autonomous procurement](https://the-rail-site.vercel.app/use-cases/autonomous-procurement/) | Bounded purchase, intervention, later refusal, and held payout | Test or stub payment infrastructure |
| [Model assurance](https://the-rail-site.vercel.app/use-cases/model-assurance/) | Configuration change makes earlier attestation inapplicable | Exported bundle supplies denial evidence; evaluations are fixtures |
| [Multi-agent delegation](https://the-rail-site.vercel.app/use-cases/multi-agent-delegation/) | Parent bounds, narrower delegation, and revocation | Recorded service identities, not a buyer-platform integration |
| [Governed reuse](https://the-rail-site.vercel.app/use-cases/governed-reuse/) | Exact artifact version, contribution, rights, and conditional settlement | Fictional integration artifact and test/stub settlement |
| [Compute governance](https://the-rail-site.vercel.app/use-cases/compute-governance/) | Measurement applicability and execution eligibility | Fixture inputs; no hardware-metering or energy-savings claim |
| [Context and consent](https://the-rail-site.vercel.app/use-cases/context-consent/) | Content checks and permission are separate | Synthetic inputs; no legal-compliance determination |

## How to use a recording

1. Read what the workflow actually demonstrates and its explicit limitations.
2. Inspect the connected decisions in the workbench.
3. Download the bundle and verification inputs.
4. Run a matching verifier with an independently confirmed trust anchor.
5. Define the additional integration and acceptance tests needed for your environment.

The workbench displays a supplied verification report. Cryptographic verification runs separately; see [the verification guide](/guides/verify-evidence).
