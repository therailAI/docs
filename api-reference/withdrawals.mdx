title: "Withdrawals API — Send Funds to External Counterparties"
sidebarTitle: "Withdrawals"
description: "Create and track outbound withdrawals from customer accounts to external counterparties via ACH, wire, and crypto. Handle Auto-RFI document requests programmatically."
---

A Withdrawal moves funds from a customer's Rail [Account](/api-reference/accounts) to an external [Counterparty](/api-reference/counterparties) — for example, disbursing earnings to a bank account or sending crypto to an external wallet. Each withdrawal specifies a source account, a destination counterparty, an amount, and an asset type. Rail performs compliance screening on each withdrawal; in some cases an **Auto-RFI** (Request for Information) may be raised, requiring you to upload supporting documents before the transaction can proceed.

---

## POST /v1/withdrawals

Creates a new withdrawal request. The source account must have sufficient available balance and be in `OPEN` status. The destination counterparty must be `ACTIVE`.

<ParamField body="source_account_id" type="string" required>
  The ID of the account from which funds will be debited (e.g. `CUST001.USD.001`).
</ParamField>

<ParamField body="destination_counterparty_id" type="string" required>
  The ID of the counterparty that will receive the funds (e.g. `cp_xyz789`).
</ParamField>

<ParamField body="amount" type="number" required>
  The amount to withdraw, in the units of the specified `asset_type`.
</ParamField>

<ParamField body="asset_type" type="string" required>
  The asset to send (e.g. `FIAT_USD`, `FIAT_TESTNET_USD`, `ETHEREUM_MAINNET_ETH`).
</ParamField>

<ParamField body="description" type="string">
  Optional memo or reference included with the payment.
</ParamField>

<ParamField body="idempotency_key" type="string">
  A unique key to safely retry the request without creating duplicate withdrawals. See [Idempotency](/api-reference/idempotency).
</ParamField>

<Warning>
  Withdrawals are processed asynchronously. A `201 Created` response means the withdrawal has been accepted and queued — it does not mean funds have left the account. Monitor status via the [GET /v1/withdrawals/{withdrawal_id}/status](#get-v1withdrawalswithdrawal_idstatus) endpoint or subscribe to `withdrawal.status.changed` webhook events.
</Warning>

```bash
curl -X POST https://sandbox.layer2financial.com/api/v1/withdrawals \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "source_account_id": "CUST001.USD.001",
    "destination_counterparty_id": "cp_xyz789",
    "amount": 1000.00,
    "asset_type": "FIAT_USD",
    "description": "Monthly payout",
    "idempotency_key": "withdrawal-20240120-001"
  }'
```

<ResponseField name="data" type="object">
  The newly created withdrawal object.
  <Expandable title="data fields">
    <ResponseField name="id" type="string">
      Unique withdrawal identifier (e.g. `wdl_abc001`).
    </ResponseField>
    <ResponseField name="source_account_id" type="string">Source account ID.</ResponseField>
    <ResponseField name="destination_counterparty_id" type="string">Destination counterparty ID.</ResponseField>
    <ResponseField name="amount" type="number">Requested withdrawal amount.</ResponseField>
    <ResponseField name="asset_type" type="string">Asset type being withdrawn.</ResponseField>
    <ResponseField name="status" type="string">
      Current status. Starts as `REQUESTED`. See status lifecycle below.
    </ResponseField>
    <ResponseField name="description" type="string">Optional memo.</ResponseField>
    <ResponseField name="created_at" type="string">ISO 8601 creation timestamp.</ResponseField>
    <ResponseField name="updated_at" type="string">ISO 8601 last-update timestamp.</ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "id": "wdl_abc001",
    "source_account_id": "CUST001.USD.001",
    "destination_counterparty_id": "cp_xyz789",
    "amount": 1000.00,
    "asset_type": "FIAT_USD",
    "status": "REQUESTED",
    "description": "Monthly payout",
    "created_at": "2024-01-20T10:00:00Z",
    "updated_at": "2024-01-20T10:00:00Z"
  }
}
```

**Withdrawal status lifecycle:**

| Status | Description |
|--------|-------------|
| `REQUESTED` | Withdrawal accepted and queued for compliance review. |
| `PENDING` | Passed initial screening; awaiting processing. |
| `PROCESSING` | Funds are in transit on the payment network. |
| `COMPLETED` | Funds have been delivered to the counterparty. |
| `FAILED` | Withdrawal could not be completed (see status endpoint for details). |
| `CANCELLED` | Withdrawal was cancelled before processing. |

## GET /v1/withdrawals

Returns a paginated list of all withdrawal records for your platform. Filter by account, counterparty, or status.

<ParamField query="source_account_id" type="string">
  Filter by source account.
</ParamField>

<ParamField query="destination_counterparty_id" type="string">
  Filter by destination counterparty.
</ParamField>

<ParamField query="status" type="string">
  Filter by withdrawal status: `REQUESTED`, `PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`, or `CANCELLED`.
</ParamField>

<ParamField query="from_date" type="string">
  Return withdrawals created on or after this ISO 8601 datetime.
</ParamField>

<ParamField query="to_date" type="string">
  Return withdrawals created on or before this ISO 8601 datetime.
</ParamField>

<ParamField query="page" type="integer">Page number. Defaults to `1`.</ParamField>
<ParamField query="page_size" type="integer">Results per page. Defaults to `20`, maximum `100`.</ParamField>

```bash
curl -X GET "https://sandbox.layer2financial.com/api/v1/withdrawals?source_account_id=CUST001.USD.001&status=COMPLETED" \
  -H "Authorization: Bearer {AUTH_TOKEN}"
```

```json
{
  "data": [
    {
      "id": "wdl_abc001",
      "source_account_id": "CUST001.USD.001",
      "destination_counterparty_id": "cp_xyz789",
      "amount": 1000.00,
      "asset_type": "FIAT_USD",
      "status": "COMPLETED",
      "description": "Monthly payout",
      "created_at": "2024-01-20T10:00:00Z",
      "updated_at": "2024-01-20T14:30:00Z"
    }
  ],
  "pagination": {
```

## GET /v1/withdrawals/{withdrawal_id}/status

Returns a detailed status object for a withdrawal, including any Auto-RFI (Request for Information) details. Poll this endpoint when you need to check whether additional documents are required.

<ParamField path="withdrawal_id" type="string" required>
  The unique withdrawal identifier.
</ParamField>

<Note>
  **Auto-RFI**: Rail's compliance engine may pause a withdrawal and raise a Request for Information if the transaction triggers enhanced due diligence. When an Auto-RFI is active, the withdrawal status will include an `rfi` object describing what documents are required. Upload documents using [POST /v1/withdrawals/{withdrawal_id}/documents](#post-v1withdrawalswithdrawal_iddocuments) to resolve the RFI and resume processing.
</Note>

```bash
curl -X GET https://sandbox.layer2financial.com/api/v1/withdrawals/wdl_abc001/status \
  -H "Authorization: Bearer {AUTH_TOKEN}"
```

<ResponseField name="data" type="object">
  Detailed status object.
  <Expandable title="data fields">
    <ResponseField name="withdrawal_id" type="string">The withdrawal ID.</ResponseField>
    <ResponseField name="status" type="string">Current processing status.</ResponseField>
    <ResponseField name="rfi" type="object">
      Present only when an Auto-RFI is active.
      <Expandable title="rfi fields">
        <ResponseField name="rfi_id" type="string">Unique identifier for this RFI.</ResponseField>
        <ResponseField name="status" type="string">`OPEN` or `RESOLVED`.</ResponseField>
        <ResponseField name="reason" type="string">Human-readable reason the RFI was raised.</ResponseField>
        <ResponseField name="required_documents" type="array">
          List of document types needed (e.g. `INVOICE`, `CONTRACT`, `PROOF_OF_FUNDS`).
        </ResponseField>
        <ResponseField name="due_by" type="string">
          ISO 8601 deadline to submit documents before the withdrawal is automatically cancelled.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="failure_reason" type="string">
      Human-readable reason for failure (present when status is `FAILED`).
    </ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "withdrawal_id": "wdl_abc001",
    "status": "PENDING",
    "rfi": {
      "rfi_id": "rfi_wd001",
      "status": "OPEN",
      "reason": "Transaction amount exceeds threshold. Supporting documentation required.",
      "required_documents": ["INVOICE", "CONTRACT"],
      "due_by": "2024-01-22T10:00:00Z"
    },
    "failure_reason": null
  }
}
```

## POST /v1/withdrawals/{withdrawal_id}/documents

Uploads one or more supporting documents to resolve an Auto-RFI on a withdrawal. Documents must be submitted as `multipart/form-data`.

<ParamField path="withdrawal_id" type="string" required>
  The unique withdrawal identifier.
</ParamField>

<ParamField body="document_type" type="string" required>
  The type of document being uploaded (e.g. `INVOICE`, `CONTRACT`, `PROOF_OF_FUNDS`). Must match one of the types listed in the active RFI's `required_documents` array.
</ParamField>

<ParamField body="file" type="file" required>
  The document file. Accepted formats: PDF, PNG, JPEG. Maximum size: 10 MB.
</ParamField>

<ParamField body="description" type="string">
  Optional description or notes about the document.
</ParamField>

<Warning>
  Documents must be uploaded before the `due_by` deadline shown in the RFI. If the deadline passes without a satisfactory submission, the withdrawal will be automatically `CANCELLED`.
</Warning>

```bash
curl -X POST https://sandbox.layer2financial.com/api/v1/withdrawals/wdl_abc001/documents \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -F "document_type=INVOICE" \
  -F "file=@/path/to/invoice.pdf" \
  -F "description=Invoice INV-2024-001 for services rendered"
```

<ResponseField name="data" type="object">
  <Expandable title="data fields">
    <ResponseField name="document_id" type="string">Unique ID of the uploaded document.</ResponseField>
    <ResponseField name="withdrawal_id" type="string">Associated withdrawal ID.</ResponseField>
    <ResponseField name="rfi_id" type="string">The RFI this document is associated with.</ResponseField>
    <ResponseField name="document_type" type="string">Type of document uploaded.</ResponseField>
    <ResponseField name="status" type="string">`UPLOADED` (pending review) or `ACCEPTED`.</ResponseField>
    <ResponseField name="uploaded_at" type="string">ISO 8601 upload timestamp.</ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "document_id": "doc_wd001",
    "withdrawal_id": "wdl_abc001",
    "rfi_id": "rfi_wd001",
    "document_type": "INVOICE",
    "status": "UPLOADED",
    "uploaded_at": "2024-01-21T09:30:00Z"
  }
}
```
