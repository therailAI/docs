OAuth2 Bearer tokens establish *who* is making a request, but they do not guarantee that the request body has not been tampered with in transit. Rail's optional request-signing feature lets you attach a cryptographic signature to each request using your private key. Rail verifies the signature on receipt — if the payload was altered after you signed it, or if the request is being replayed from a previous capture, Rail rejects it. Signing is strongly recommended for any integration that initiates withdrawals, exchanges, or other high-value operations.

<Note>
  Request signing is optional but recommended for production integrations that move funds. Contact your Rail account manager to enable signing enforcement on your credentials, which will cause unsigned requests to be rejected.
</Note>

## How Signing Works

When you enable request signing, you sign a canonical string that encodes the HTTP method, path, timestamp, and a hash of the request body. Rail reconstructs the same canonical string from the incoming request and verifies the signature against your registered public key. Any modification to the method, path, timestamp, or body invalidates the signature.

## Signing Algorithm

Rail supports two signature algorithms:

| Algorithm | Identifier | Key Type |
|-----------|------------|----------|
| RSA-SHA256 | `RS256` | RSA private/public key pair (2048-bit minimum) |
| HMAC-SHA256 | `HS256` | Shared secret |

RS256 with an asymmetric key pair is recommended for production — you register the public key with Rail and keep the private key exclusively on your servers.

## Step-by-Step Signing Process

<Steps>
  <Step title="Compute the body hash">
    Take the raw UTF-8 request body string and compute its SHA-256 hash, then Base64-encode the result. For requests with no body (e.g., GET requests), use the hash of an empty string.

    ```text
    BODY_HASH = Base64(SHA256(request_body_utf8))
    ```
  </Step>

  <Step title="Build the canonical string">
    Concatenate the following fields, each separated by a newline character (`\n`):

    ```text
    {HTTP_METHOD}\n{PATH}\n{TIMESTAMP}\n{BODY_HASH}
    ```

    Where:
    - `HTTP_METHOD` — uppercase verb, e.g. `POST`
    - `PATH` — the request path including query string, e.g. `/v1/withdrawals`
    - `TIMESTAMP` — Unix timestamp in seconds (integer), e.g. `1717200000`
    - `BODY_HASH` — the Base64-encoded SHA-256 body hash from Step 1

    Example canonical string:
    ```text
    POST
    /v1/withdrawals
    1717200000
    47DEQpj8HBSa+/TImW+5JCeuQeRkm5NMpJWZG3hSuFU=
    ```
  </Step>

  <Step title="Sign the canonical string">
    Sign the canonical string bytes using your private key and the chosen algorithm:

    - **RS256**: Sign with your RSA private key using PKCS#1 v1.5 padding and SHA-256 digest.
    - **HS256**: Compute HMAC-SHA256 of the canonical string using your shared secret.

    Base64-encode the resulting signature bytes.
  </Step>

  <Step title="Add the required headers">
    Include two additional headers on the request:

    | Header | Value |
    |--------|-------|
    | `X-Rail-Signature` | The Base64-encoded signature from Step 3 |
    | `X-Rail-Timestamp` | The same Unix timestamp used in the canonical string |

    ```http
    X-Rail-Signature: {BASE64_SIGNATURE}
    X-Rail-Timestamp: 1717200000
    ```
  </Step>
</Steps>

## Required Headers Summary

<ParamField header="X-Rail-Signature" type="string" required>
  Base64-encoded cryptographic signature of the canonical string. Computed using RS256 or HS256.
</ParamField>

<ParamField header="X-Rail-Timestamp" type="integer" required>
  Unix timestamp (seconds) at which the request was signed. Must be within 5 minutes of Rail's server clock.
</ParamField>

## Replay Attack Protection

Rail maintains a 5-minute replay window. Any request whose `X-Rail-Timestamp` differs from Rail's current server time by more than **300 seconds** — in either direction — is rejected with `400 Bad Request`. This prevents an attacker who captures a valid signed request from replaying it later.

<Warning>
  Ensure your server clock is synchronized with an NTP source. Clock drift beyond a few seconds can cause legitimate requests to be rejected, even with a valid signature.
</Warning>

## Code Examples

<Tabs>
  <Tab title="cURL">
    The following shell script computes and attaches a signature to a withdrawal request using `openssl`:

    ```bash
    #!/bin/bash

    METHOD="POST"
    PATH="/v1/withdrawals"
    TIMESTAMP=$(date +%s)
    BODY='{"account_id":"acct_01HZ4K2X9V3N8FQRTW6YDCBME","amount":"500.00","currency":"USD","counterparty_id":"cpty_9XKQV2M7P"}'
    PRIVATE_KEY_PATH="./private_key.pem"

    # Step 1: Compute body hash
    BODY_HASH=$(echo -n "$BODY" | openssl dgst -sha256 -binary | base64)

    # Step 2: Build canonical string
    CANONICAL="${METHOD}\n${PATH}\n${TIMESTAMP}\n${BODY_HASH}"

    # Step 3: Sign the canonical string
    SIGNATURE=$(printf '%b' "$CANONICAL" | openssl dgst -sha256 -sign "$PRIVATE_KEY_PATH" -binary | base64)

    # Step 4: Make the request
    curl --request POST \
      'https://sandbox.layer2financial.com/api/v1/withdrawals' \
      --header "Authorization: Bearer {AUTH_TOKEN}" \
      --header "Content-Type: application/json" \
      --header "X-Rail-Signature: ${SIGNATURE}" \
      --header "X-Rail-Timestamp: ${TIMESTAMP}" \
      --data "$BODY"
    ```
  </Tab>

  <Tab title="Node.js">
    ```javascript
    const crypto = require('crypto');
    const fs = require('fs');

    function signRequest({ method, path, body, privateKeyPath }) {
      const timestamp = Math.floor(Date.now() / 1000);

      // Step 1: Compute body hash
      const bodyHash = crypto
        .createHash('sha256')
        .update(body, 'utf8')
        .digest('base64');

      // Step 2: Build canonical string
      const canonical = [method.toUpperCase(), path, timestamp, bodyHash].join('\n');

      // Step 3: Sign with RS256
      const privateKey = fs.readFileSync(privateKeyPath, 'utf8');
      const signature = crypto
        .createSign('SHA256')
        .update(canonical, 'utf8')
        .sign(privateKey, 'base64');

      return { signature, timestamp };
    }

    // Usage
    const body = JSON.stringify({
      account_id: 'acct_01HZ4K2X9V3N8FQRTW6YDCBME',
      amount: '500.00',
      currency: 'USD',
      counterparty_id: 'cpty_9XKQV2M7P',
    });

    const { signature, timestamp } = signRequest({
      method: 'POST',
      path: '/v1/withdrawals',
      body,
      privateKeyPath: './private_key.pem',
    });

    const response = await fetch(
      'https://sandbox.layer2financial.com/api/v1/withdrawals',
      {
        method: 'POST',
        headers: {
          Authorization: 'Bearer {AUTH_TOKEN}',
          'Content-Type': 'application/json',
          'X-Rail-Signature': signature,
          'X-Rail-Timestamp': String(timestamp),
        },
        body,
      }
    );
    ```

  <Tab title="Python">
    ```python
    import hashlib
    import base64
    import time
    import json
    from cryptography.hazmat.primitives import hashes, serialization
    from cryptography.hazmat.primitives.asymmetric import padding
    import requests

    def sign_request(method: str, path: str, body: str, private_key_path: str):
        timestamp = int(time.time())

        # Step 1: Compute body hash
        body_hash = base64.b64encode(
            hashlib.sha256(body.encode('utf-8')).digest()
        ).decode()

        # Step 2: Build canonical string
        canonical = f"{method.upper()}\n{path}\n{timestamp}\n{body_hash}"

        # Step 3: Sign with RS256
        with open(private_key_path, 'rb') as f:
            private_key = serialization.load_pem_private_key(f.read(), password=None)

        signature = base64.b64encode(
            private_key.sign(
                canonical.encode('utf-8'),
                padding.PKCS1v15(),
                hashes.SHA256(),
            )
        ).decode()

        return signature, timestamp


    # Usage
    body = json.dumps({
        'account_id': 'acct_01HZ4K2X9V3N8FQRTW6YDCBME',
        'amount': '500.00',
        'currency': 'USD',
        'counterparty_id': 'cpty_9XKQV2M7P',
    })

    signature, timestamp = sign_request(
        method='POST',
        path='/v1/withdrawals',
        body=body,
        private_key_path='./private_key.pem',
    )

    response = requests.post(
        'https://sandbox.layer2financial.com/api/v1/withdrawals',
        headers={
            'Authorization': 'Bearer {AUTH_TOKEN}',
            'Content-Type': 'application/json',
            'X-Rail-Signature': signature,
            'X-Rail-Timestamp': str(timestamp),
        },
        data=body,
    )
    ```

## Registering Your Public Key

To use RS256 signing, register your RSA public key in the Rail developer dashboard under **Settings → API Security → Signing Keys**. Rail uses this public key to verify all incoming signatures. You can register multiple keys to support key rotation without downtime — Rail accepts signatures from any registered active key.

<Tip>
  Generate a 2048-bit (minimum) or 4096-bit RSA key pair. Never upload your private key — Rail only needs the public key for verification.

  ```bash
  # Generate a 4096-bit RSA key pair
  openssl genrsa -out private_key.pem 4096
  openssl rsa -in private_key.pem -pubout -out public_key.pem
  ```
</Tip>

## Signing Errors

| HTTP Status | Cause | Resolution |
|-------------|-------|------------|
| `400 Bad Request` | `X-Rail-Timestamp` is outside the 5-minute window | Check server clock synchronization; ensure you use the timestamp at request time, not build time |
| `400 Bad Request` | `X-Rail-Signature` header is missing when signing is enforced | Add the signature headers to every request |
| `401 Unauthorized` | Signature verification failed | Verify the canonical string construction; ensure you're signing the exact body bytes sent in the request |
