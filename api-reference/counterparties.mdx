title: "Counterparties API — Manage External Payment Parties"
sidebarTitle: "Counterparties"
description: "Create and manage counterparties — external individuals or businesses your customers transact with via ACH, wire, crypto, and linked bank accounts."
---

A Counterparty represents an external party — an individual or business — that a [Customer](/api-reference/customers) transacts with. Before your customer can send a [Withdrawal](/api-reference/withdrawals) or receive a [Payment](/api-reference/payments), a Counterparty record must exist to identify the destination or source. Rail supports four counterparty types: `BASIC` (identity profile only), `FIAT_US` (US bank account), `CRYPTO` (blockchain address), and `LINKED` (bank account connected via Plaid or MX for instant verification and pull payments). Counterparties progress from `PENDING` → `ACTIVE` once validated.

---

## POST /v1/counterparties

Creates a new counterparty for a customer. The structure of the request body varies depending on `counterparty_type`.

<ParamField body="customer_id" type="string" required>
  The ID of the customer who owns this counterparty relationship.
</ParamField>

<ParamField body="counterparty_type" type="string" required>
  The type of counterparty. One of: `BASIC`, `FIAT_US`, `CRYPTO`, `LINKED`.
</ParamField>

<ParamField body="profile" type="object" required>
  Identity profile for the counterparty.
  <Expandable title="profile fields">
    <ParamField body="profile_type" type="string" required>
      `INDIVIDUAL` or `BUSINESS`.
    </ParamField>
    <ParamField body="name" type="string" required>
      Full legal name of the individual or business.
    </ParamField>
    <ParamField body="address" type="object">
      Counterparty address.
      <Expandable title="address fields">
        <ParamField body="street_line_1" type="string">Primary street address.</ParamField>
        <ParamField body="city" type="string">City.</ParamField>
        <ParamField body="state" type="string">Two-letter state code.</ParamField>
        <ParamField body="postal_code" type="string">ZIP or postal code.</ParamField>
        <ParamField body="country_code" type="string" required>ISO 3166-1 alpha-2 country code.</ParamField>
      </Expandable>
    </ParamField>
    <ParamField body="relationship_to_customer" type="string">
      Describes the relationship (e.g. `CUSTOMER`, `VENDOR`, `EMPLOYEE`, `SELF`). Used for compliance purposes.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="bank_account" type="object">
  Required for `FIAT_US` type. US bank account details for ACH or wire payments.
  <Expandable title="bank_account fields">
    <ParamField body="routing_number" type="string" required>ABA routing number.</ParamField>
    <ParamField body="account_number" type="string" required>Bank account number.</ParamField>
    <ParamField body="account_type" type="string" required>`CHECKING` or `SAVINGS`.</ParamField>
    <ParamField body="bank_name" type="string">Name of the bank.</ParamField>
  </Expandable>
</ParamField>

<ParamField body="crypto_address" type="object">
  Required for `CRYPTO` type. Blockchain address details.
  <Expandable title="crypto_address fields">
    <ParamField body="address" type="string" required>The blockchain wallet address.</ParamField>
    <ParamField body="network" type="string" required>
      The blockchain network (e.g. `ETHEREUM_MAINNET`, `BITCOIN_MAINNET`, `POLYGON_MAINNET`).
    </ParamField>
    <ParamField body="asset_type" type="string" required>
      Asset type for this address (e.g. `ETHEREUM_MAINNET_ETH`, `BITCOIN_MAINNET_BTC`).
    </ParamField>
  </Expandable>
</ParamField>

<Tip>
  For `LINKED` counterparties, create the record with `counterparty_type: "LINKED"` and then use the `/link/details`, `/link/accounts`, and `/link/connect` sub-endpoints to complete the bank account linking flow via Plaid or MX.
</Tip>

<CodeGroup>

```bash BASIC counterparty
curl -X POST https://sandbox.layer2financial.com/api/v1/counterparties \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": "CUST001",
    "counterparty_type": "BASIC",
    "profile": {
      "profile_type": "INDIVIDUAL",
      "name": "Joe Bloggs",
      "address": {
        "state": "MA",
        "country_code": "US"
      },
      "relationship_to_customer": "CUSTOMER"
    }
  }'
```

```bash FIAT_US counterparty

    "customer_id": "CUST001",
    "counterparty_type": "FIAT_US",
    "profile": {

      "name": "Joe Bloggs",
      "address": {
        "state": "MA",
        "country_code": "US"
      },
      "relationship_to_customer": "CUSTOMER"
    },
    "bank_account": {
      "routing_number": "021000021",
      "account_number": "987654321",
      "account_type": "CHECKING",
      "bank_name": "Chase Bank"
    }
  }'
```

```bash CRYPTO counterparty
curl -X POST https://sandbox.layer2financial.com/api/v1/counterparties \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": "CUST001",
    "counterparty_type": "CRYPTO",
    "profile": {
      "profile_type": "INDIVIDUAL",
      "name": "Joe Bloggs",

    "crypto_address": {
      "address": "0xAbCdEf1234567890AbCdEf1234567890AbCdEf12",
      "network": "ETHEREUM_MAINNET",
      "asset_type": "ETHEREUM_MAINNET_ETH"
    }
  }'
```

</CodeGroup>

<ResponseField name="data" type="object">
  The newly created counterparty.
  <Expandable title="data fields">
    <ResponseField name="id" type="string">Unique counterparty identifier (e.g. `cp_xyz789`).</ResponseField>
    <ResponseField name="customer_id" type="string">Owning customer ID.</ResponseField>
    <ResponseField name="counterparty_type" type="string">`BASIC`, `FIAT_US`, `CRYPTO`, or `LINKED`.</ResponseField>
    <ResponseField name="status" type="string">

    <ResponseField name="profile" type="object">Submitted profile details.</ResponseField>
    <ResponseField name="bank_account" type="object">Bank account details (FIAT_US only).</ResponseField>
    <ResponseField name="crypto_address" type="object">Crypto address details (CRYPTO only).</ResponseField>
    <ResponseField name="created_at" type="string">ISO 8601 creation timestamp.</ResponseField>
  </Expandable>
</ResponseField>

## GET /v1/counterparties

Returns a paginated list of counterparties. Filter by customer or status.

<ParamField query="customer_id" type="string">
  Return only counterparties belonging to this customer.
</ParamField>

<ParamField query="status" type="string">
  Filter by status: `PENDING`, `ACTIVE`, `SUSPENDED`, or `REJECTED`.
</ParamField>

<ParamField query="counterparty_type" type="string">
  Filter by type: `BASIC`, `FIAT_US`, `CRYPTO`, or `LINKED`.
</ParamField>

<ParamField query="page" type="integer">Page number. Defaults to `1`.</ParamField>
<ParamField query="page_size" type="integer">Results per page. Defaults to `20`, maximum `100`.</ParamField>

```bash
curl -X GET "https://sandbox.layer2financial.com/api/v1/counterparties?customer_id=CUST001&status=ACTIVE" \
  -H "Authorization: Bearer {AUTH_TOKEN}"
```

```json
{
  "data": [
    {
      "id": "cp_xyz789",
      "customer_id": "CUST001",
      "counterparty_type": "BASIC",
      "status": "ACTIVE",
      "profile": {
        "profile_type": "INDIVIDUAL",
        "name": "Joe Bloggs"
      },
      "created_at": "2024-01-17T11:00:00Z"
    }
  ],
  "pagination": {
    "total": 1,
    "page": 1,
    "page_size": 20,
    "total_pages": 1
  }
}
```

## PATCH /v1/counterparties/{counterparty_id}

Updates a counterparty's profile or bank account details. Only counterparties with `ACTIVE` or `PENDING` status can be updated.

<ParamField path="counterparty_id" type="string" required>
  The unique identifier of the counterparty to update.
</ParamField>

<ParamField body="profile" type="object">
  Updated profile fields (partial update supported).
</ParamField>

<ParamField body="bank_account" type="object">

</ParamField>

```bash
curl -X PATCH https://sandbox.layer2financial.com/api/v1/counterparties/cp_xyz789 \

  -H "Content-Type: application/json" \
```

## POST /v1/counterparties/{counterparty_id}/link/details

Initiates a bank-linking session for a `LINKED` counterparty. Returns the configuration and tokens required to launch the Plaid Link or MX Connect widget in your UI.

<ParamField path="counterparty_id" type="string" required>
  The ID of the `LINKED` counterparty for which to generate linking instructions.
</ParamField>

<ParamField body="link_provider" type="string" required>
  The linking provider to use: `PLAID` or `MX`.
</ParamField>

```bash
curl -X POST https://sandbox.layer2financial.com/api/v1/counterparties/cp_link001/link/details \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "link_provider": "PLAID"
  }'
```

<ResponseField name="data" type="object">
  <Expandable title="data fields">
    <ResponseField name="link_provider" type="string">The chosen provider (`PLAID` or `MX`).</ResponseField>
    <ResponseField name="link_token" type="string">
      Token to initialize the provider's widget (Plaid `link_token` or MX widget URL).
    </ResponseField>
    <ResponseField name="expires_at" type="string">ISO 8601 expiry of the link token.</ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "link_provider": "PLAID",
    "link_token": "link-sandbox-abc123def456",
    "expires_at": "2024-01-17T11:30:00Z"
  }
}
```

## POST /v1/counterparties/{counterparty_id}/link/accounts

Lists the bank accounts available to link after the customer has authenticated with Plaid or MX. Call this endpoint with the public token returned by the link widget.

<ParamField path="counterparty_id" type="string" required>
  The ID of the `LINKED` counterparty.
</ParamField>

<ParamField body="public_token" type="string" required>
  The public token returned by the Plaid or MX widget after successful authentication.
</ParamField>

```bash
curl -X POST https://sandbox.layer2financial.com/api/v1/counterparties/cp_link001/link/accounts \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "public_token": "public-sandbox-token-xyz"
  }'
```

```json
{
  "data": {
    "linkable_accounts": [
      {
        "link_account_id": "la_001",
        "account_name": "Plaid Checking",
        "account_type": "CHECKING",
        "account_mask": "0000",
        "institution_name": "Chase Bank"
      },
      {
        "link_account_id": "la_002",
        "account_name": "Plaid Savings",
        "account_type": "SAVINGS",
        "account_mask": "1111",
        "institution_name": "Chase Bank"
      }
    ]
  }
}
```

## POST /v1/counterparties/{counterparty_id}/link/connect

Completes the bank-linking process by connecting a specific account from the list returned by `/link/accounts`. After a successful call, the counterparty status transitions to `ACTIVE`.

<ParamField path="counterparty_id" type="string" required>
  The ID of the `LINKED` counterparty.
</ParamField>

<ParamField body="public_token" type="string" required>
  The public token from the link widget.
</ParamField>

<ParamField body="link_account_id" type="string" required>
  The `link_account_id` of the account to connect, as returned by `/link/accounts`.
</ParamField>

```bash
curl -X POST https://sandbox.layer2financial.com/api/v1/counterparties/cp_link001/link/connect \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "public_token": "public-sandbox-token-xyz",
    "link_account_id": "la_001"
  }'
```

```json
{
  "data": {
    "id": "cp_link001",
    "customer_id": "CUST001",
    "counterparty_type": "LINKED",
    "status": "ACTIVE",
    "linked_account": {
      "institution_name": "Chase Bank",
      "account_name": "Plaid Checking",
      "account_type": "CHECKING",
      "account_mask": "0000"
    },
    "updated_at": "2024-01-17T11:20:00Z"
  }
}
```
