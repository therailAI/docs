---
title: "Errors and recovery"
description: "Interpret HTTP problems, durable denial, and external-effect uncertainty."
---

Rail uses RFC 9457 problem details. A problem includes `type`, `title`, `status`, `code`, and `request_id`. It can also identify an execution, denial receipt, or field-level errors.

| Status | Next step |
| --- | --- |
| `400` | Correct request syntax, cursor, or another invalid parameter |
| `401` | Check token validity, issuer, audience, active enrollment, and certificate binding |
| `403` | Check effective scopes, eligible roles, and domain authority |
| `404` | Check the authorized resource identifier; do not infer cross-tenant existence |
| `409` | Inspect the typed problem: duplicate content, pending work, or unresolved effects need different handling |
| `412`, `428` | Re-read the resource or supply the required concurrency precondition |
| `413` | Reduce the payload or use the supported object-upload flow |
| `422` | Correct schema or semantic constraints |
| `429` | Respect bounded backoff and `Retry-After`; preserve operation identity |
| `500`, `503` | Inspect whether submission or an external effect may have occurred before recovery |

Not every endpoint returns every status. Its reference page lists the contract responses. The shared server can additionally reject a request before the handler, for example with `400` for invalid parameters or `413` for an oversized body. Contract response coverage is not an exhaustive list of every intermediary or transport failure.

`503` can mean a missing governance profile, unsupported obligation, or unavailable integration, as well as transient infrastructure failure. Read the problem type and the endpoint's implementation notes before choosing to retry.

## A denial can arrive after HTTP acceptance

Execution submission returns `202` for asynchronous processing. Later governance denial is visible through the execution state, basis codes, and receipts. Do not treat `202` as approval or completion.

A domain denial can have a durable denial receipt when a canonical action exists. An authentication failure before canonicalization does not claim an action receipt. A failure to durably commit evidence must not be described as a committed denial.

## An uncertain effect needs reconciliation

`UNRESOLVED_EXTERNAL_EFFECT` means that repetition or substitution cannot yet be established as safe. Preserve the original identity and use the [recovery flow](/guides/recovery).

Log request IDs and the minimum necessary diagnostic fields. Do not expose credentials, protected inputs, internal policy details, or cross-tenant information in user-facing errors.
