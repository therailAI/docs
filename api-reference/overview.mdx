Rail exposes a single, versioned REST API that lets you build compliant fiat and digital-asset financial products — customer onboarding, accounts, deposits, withdrawals, transfers, exchanges, and more — through a consistent JSON interface. Every request is authenticated with short-lived OAuth2 Bearer tokens, and every response is wrapped in a top-level `data` envelope for predictable parsing. This page orients you to the API's structure, base URLs, and the supporting reference topics you'll use most.

## Base URLs

All API calls are made over HTTPS. Use the sandbox environment to develop and test your integration without touching real funds; switch to the production URL when you're ready to go live.

| Environment | Base URL |
|-------------|----------|
| Sandbox | `https://sandbox.layer2financial.com/api` |
| Production | `https://platform.layer2financial.com/api` |

<Note>
  Always use the sandbox environment during development. Sandbox credentials and production credentials are issued separately — they cannot be interchanged.
</Note>

## API Version

The current API release is **v1.1.2**. Every endpoint path is prefixed with `/v1/`, for example:

```http
GET https://sandbox.layer2financial.com/api/v1/accounts
```

Breaking changes will be introduced under a new version path (e.g., `/v2/`). Non-breaking additions — new optional fields, new endpoints — may be added to v1 at any time.

## Request and Response Format

All request bodies and response bodies use `application/json`. Set the `Content-Type` header on every mutating request:

```http
Content-Type: application/json
```

Successful responses wrap the primary payload in a `data` key:

```json
{
  "data": {
    "id": "acct_01HZ4K2X9V3N8FQRTW6YDCBME",
    "type": "CHECKING",
    "status": "OPEN",
    "balance": "1000.00",
    "currency": "USD"
  }
}
```

List responses include a `pagination` object alongside `data` — see [Pagination](api-reference/pagination) for details.

## Your First API Call

The example below fetches a list of accounts in the sandbox. Replace `{AUTH_TOKEN}` with the Bearer token you obtain from the [authentication flow](api-reference/authentication).

<CodeGroup>

```bash cURL
curl --request GET \
  'https://sandbox.layer2financial.com/api/v1/accounts' \
  --header 'Authorization: Bearer {AUTH_TOKEN}' \
  --header 'Content-Type: application/json'
```

```javascript Node.js
const response = await fetch(
  'https://sandbox.layer2financial.com/api/v1/accounts',
  {
    method: 'GET',
    headers: {
      Authorization: 'Bearer {AUTH_TOKEN}',
      'Content-Type': 'application/json',
    },
  }
);
const { data } = await response.json();
console.log(data);
```

```python Python
import requests

response = requests.get(
    'https://sandbox.layer2financial.com/api/v1/accounts',
    headers={
        'Authorization': 'Bearer {AUTH_TOKEN}',
        'Content-Type': 'application/json',
    },
)
data = response.json()['data']
print(data)
```

</CodeGroup>

A successful response returns HTTP `200` with the accounts list nested under `data`.
