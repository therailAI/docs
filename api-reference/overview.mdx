The reference contains **127 customer operations** across six product groups, shared platform operations, and advanced routing and edge surfaces. It excludes private service and trusted-runtime ingress.

[Download the bundled OpenAPI document](/api-reference/openapi.json).

## Connection and availability

Use your operator-provided customer API endpoint. The `.invalid` server and identity URLs in the contract are deliberately non-routable examples. The reference does not establish a shared hosted sandbox or availability of every operation in your deployment. See [environment status](/get-started/environment).

The API playground is read-only in this documentation. Use your qualified environment and client for actual calls.

## Request conventions

- Authenticate using OAuth and the appropriate scope. Tenant, project, object, and domain authorization are also enforced.
- Send JSON using `Content-Type: application/json`. Use UTF-8, UTC timestamps, exact decimal strings, and pinned version references.
- Supply `Idempotency-Key` on mutations and `If-Match` when the operation requires it.
- Treat HTTP acceptance, execution state, verification, and settlement as different outcomes.
- Preserve `X-Request-Id` for diagnostics without logging tokens, capabilities, private payloads, or secrets.

JSON request limits and object-upload limits are defined in the contract and deployment profile. Ordinary JSON requests are bounded at 1 MiB unless a tighter operation-specific limit applies; protected object upload sessions have a separate bound.
