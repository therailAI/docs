A Customer record is created automatically by Rail when an [Application](/api-reference/applications) is approved. Customers are the central identity object on the platform — they own [Accounts](/api-reference/accounts), initiate money movement, and are linked to [Counterparties](/api-reference/counterparties). You cannot create customers directly; instead, you manage them through this API once they exist. Corporate customers may have one or more associated individual officers, each with their own profile and compliance status.

---

## GET /v1/customers/{customer_id}

Retrieves the full profile for a single customer, including their type, status, and contact details.

<ParamField path="customer_id" type="string" required>
  The unique identifier for the customer (e.g. `CUST001`).
</ParamField>

```bash
curl -X GET https://sandbox.layer2financial.com/api/v1/customers/CUST001 \
  -H "Authorization: Bearer {AUTH_TOKEN}"
```

<ResponseField name="data" type="object">
  The customer profile object.
  <Expandable title="data fields">
    <ResponseField name="id" type="string">
      Unique customer identifier.
    </ResponseField>
    <ResponseField name="status" type="string">
      Current status of the customer. One of: `ACTIVE`, `SUSPENDED`.
    </ResponseField>
    <ResponseField name="customer_type" type="string">
      `INDIVIDUAL` or `CORPORATION`.
    </ResponseField>
    <ResponseField name="email" type="string">
      Primary contact email address.
    </ResponseField>
    <ResponseField name="profile" type="object">
      Customer identity details (name, address, date of birth for individuals; business name and registration details for corporations).
    </ResponseField>
    <ResponseField name="application_id" type="string">
      The ID of the originating application.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when the customer record was created.
    </ResponseField>
    <ResponseField name="updated_at" type="string">
      ISO 8601 timestamp of the most recent update.
    </ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "id": "CUST001",
    "status": "ACTIVE",
    "customer_type": "INDIVIDUAL",
    "email": "jane.doe@example.com",
    "profile": {
      "first_name": "Jane",
      "last_name": "Doe",
      "date_of_birth": "1990-01-01",
      "address": {
        "street_line_1": "123 Main St",
        "city": "New York",
        "state": "NY",
        "postal_code": "10001",
        "country_code": "US"
      }
    },
    "application_id": "app_abc123",
    "created_at": "2024-01-16T09:00:00Z",
    "updated_at": "2024-01-16T09:00:00Z"
  }
}
```

## PATCH /v1/customers/{customer_id}

Updates non-compliance fields on an existing customer record, such as contact email or mailing address. Changes to identity fields (legal name, date of birth) may require a new compliance review.

<ParamField path="customer_id" type="string" required>
  The unique identifier for the customer to update.
</ParamField>

<ParamField body="email" type="string">
  Updated primary contact email address.
</ParamField>

<ParamField body="profile" type="object">
  Partial profile update. Only include the fields you want to change.
  <Expandable title="profile fields">
    <ParamField body="address" type="object">
      Updated address.
      <Expandable title="address fields">
        <ParamField body="street_line_1" type="string">Primary street address line.</ParamField>
        <ParamField body="street_line_2" type="string">Apartment or suite number.</ParamField>
        <ParamField body="city" type="string">City.</ParamField>
        <ParamField body="state" type="string">Two-letter state code.</ParamField>
        <ParamField body="postal_code" type="string">ZIP or postal code.</ParamField>
        <ParamField body="country_code" type="string">ISO 3166-1 alpha-2 country code.</ParamField>
      </Expandable>
    </ParamField>
  </Expandable>
</ParamField>

<Warning>
  You cannot update a customer whose status is `SUSPENDED`. Attempting to do so will return a `409 Conflict` error. Contact Rail support to reinstate the customer first.
</Warning>

```bash
curl -X PATCH https://sandbox.layer2financial.com/api/v1/customers/CUST001 \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jane.updated@example.com",
    "profile": {
      "address": {
        "street_line_1": "789 Park Ave",
        "city": "New York",
        "state": "NY",
        "postal_code": "10021",
        "country_code": "US"
      }
    }
  }'
```

<ResponseField name="data" type="object">
  The updated customer profile.
  <Expandable title="data fields">
    <ResponseField name="id" type="string">Customer identifier.</ResponseField>
    <ResponseField name="status" type="string">Customer status.</ResponseField>
    <ResponseField name="customer_type" type="string">`INDIVIDUAL` or `CORPORATION`.</ResponseField>
    <ResponseField name="email" type="string">Updated email address.</ResponseField>
    <ResponseField name="profile" type="object">Updated profile details.</ResponseField>
    <ResponseField name="updated_at" type="string">ISO 8601 timestamp of the update.</ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "id": "CUST001",
    "status": "ACTIVE",
    "customer_type": "INDIVIDUAL",
    "email": "jane.updated@example.com",
    "profile": {
      "first_name": "Jane",
      "last_name": "Doe",
      "date_of_birth": "1990-01-01",
      "address": {
        "street_line_1": "789 Park Ave",
        "city": "New York",
        "state": "NY",
        "postal_code": "10021",
        "country_code": "US"
      }
    },
    "updated_at": "2024-01-20T14:30:00Z"
  }
}
```

## GET /v1/customers/{customer_id}/individuals/{individual_id}

Retrieves the profile of an individual officer or beneficial owner associated with a corporate customer. This endpoint is only applicable to customers of type `CORPORATION`.

<ParamField path="customer_id" type="string" required>
  The unique identifier of the corporation customer.
</ParamField>

<ParamField path="individual_id" type="string" required>
  The unique identifier of the individual officer to retrieve.
</ParamField>

<Note>
  Individual IDs on a Customer correspond to the individual IDs added during the corporate application process via [POST /v1/applications/{application_id}/individual](/api-reference/applications).
</Note>

```bash
curl -X GET https://sandbox.layer2financial.com/api/v1/customers/CUST_CORP002/individuals/ind_def456 \
  -H "Authorization: Bearer {AUTH_TOKEN}"
```

<ResponseField name="data" type="object">
  The individual officer profile.
  <Expandable title="data fields">
    <ResponseField name="individual_id" type="string">
      Unique identifier for this individual.
    </ResponseField>
    <ResponseField name="customer_id" type="string">
      The corporation customer this individual is associated with.
    </ResponseField>
    <ResponseField name="first_name" type="string">Legal first name.</ResponseField>
    <ResponseField name="last_name" type="string">Legal last name.</ResponseField>
    <ResponseField name="email" type="string">Contact email.</ResponseField>
    <ResponseField name="date_of_birth" type="string">Date of birth (`YYYY-MM-DD`).</ResponseField>
    <ResponseField name="role" type="string">
      Role in the corporation (e.g. `BENEFICIAL_OWNER`, `OFFICER`, `DIRECTOR`).
    </ResponseField>
    <ResponseField name="status" type="string">
      KYC status for this individual: `APPROVED`, `PENDING`, or `CHANGES_REQUESTED`.
    </ResponseField>
    <ResponseField name="address" type="object">Residential address.</ResponseField>
    <ResponseField name="created_at" type="string">ISO 8601 creation timestamp.</ResponseField>
    <ResponseField name="updated_at" type="string">ISO 8601 last-update timestamp.</ResponseField>
  </Expandable>
</ResponseField>

```json

  "data": {

    "first_name": "John",
    "last_name": "Smith",
    "email": "john.smith@acmecorp.com",
    "date_of_birth": "1975-06-15",
    "role": "BENEFICIAL_OWNER",
    "status": "APPROVED",
    "address": {
      "street_line_1": "456 Corporate Blvd",
      "city": "Boston",
      "state": "MA",
      "postal_code": "02101",
      "country_code": "US"
    },
    "created_at": "2024-01-15T13:00:00Z",
    "updated_at": "2024-01-16T09:00:00Z"
  }
}
```

## PATCH /v1/customers/{customer_id}/individuals/{individual_id}

Updates profile information for an individual officer on a corporate customer record. As with the customer-level PATCH, identity-sensitive fields may trigger a compliance re-review.

<ParamField path="customer_id" type="string" required>

</ParamField>

<ParamField path="individual_id" type="string" required>
  The unique identifier of the individual to update.
</ParamField>

<ParamField body="email" type="string">
  Updated contact email for the individual.
</ParamField>

<ParamField body="role" type="string">
  Updated role in the corporation.
</ParamField>

<ParamField body="address" type="object">
  Updated residential address.
  <Expandable title="address fields">
    <ParamField body="street_line_1" type="string">Primary street address.</ParamField>
    <ParamField body="street_line_2" type="string">Apartment or suite number.</ParamField>
    <ParamField body="city" type="string">City.</ParamField>
    <ParamField body="state" type="string">Two-letter state code.</ParamField>
    <ParamField body="postal_code" type="string">ZIP or postal code.</ParamField>
    <ParamField body="country_code" type="string">ISO 3166-1 alpha-2 country code.</ParamField>
  </Expandable>
</ParamField>

```bash
curl -X PATCH https://sandbox.layer2financial.com/api/v1/customers/CUST_CORP002/individuals/ind_def456 \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "j.smith.new@acmecorp.com",
    "address": {
      "street_line_1": "100 New Office Way",
      "city": "Cambridge",
      "state": "MA",
```
