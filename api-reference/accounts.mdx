---

Accounts are the financial containers on Rail where customer funds are held. Each account is tied to a single [Customer](/api-reference/customers), holds a specific asset type (e.g. `FIAT_USD`, `ETHEREUM_MAINNET_ETH`), and is governed by a product configuration. Once an account is open, you can retrieve its balance, pull transaction history, download statements, and get deposit instructions that your customers can share with payers. Accounts progress through a lifecycle: `PENDING_APPROVAL` → `OPEN` → `SUSPENDED` or `CLOSED`.

---

## POST /v1/accounts/deposits

Opens a new deposit account for an existing customer. The account ID you provide must be unique within your platform and typically encodes the customer, asset, and a sequence number (e.g. `CUST001.USD.001`).

<ParamField body="customer_id" type="string" required>
  The ID of the customer who will own this account.
</ParamField>

<ParamField body="account_to_open" type="object" required>
  Details of the account to open.
  <Expandable title="account_to_open fields">
    <ParamField body="account_id" type="string" required>
      Your chosen unique identifier for this account (e.g. `CUST001.USD.001`). Must be unique across all accounts on your platform.
    </ParamField>
    <ParamField body="product_id" type="string" required>
      The Rail product that governs this account (e.g. `DEPOSIT_FORT_FIAT`, `DEPOSIT_FORT_CRYPTO`). Contact your Rail representative for available product IDs.
    </ParamField>
    <ParamField body="asset_type_id" type="string" required>
      The asset this account will hold (e.g. `FIAT_TESTNET_USD` in sandbox, `FIAT_USD` in production). See [Assets](/concepts/assets) for a full list.
    </ParamField>
  </Expandable>
</ParamField>

<Note>
  In sandbox, use `FIAT_TESTNET_USD` as the `asset_type_id` for US dollar accounts. In production, use `FIAT_USD`. Digital asset accounts use identifiers such as `ETHEREUM_MAINNET_ETH` or `BITCOIN_MAINNET_BTC`.
</Note>

```bash
curl -X POST https://sandbox.layer2financial.com/api/v1/accounts/deposits \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": "CUST001",
    "account_to_open": {
      "account_id": "CUST001.USD.001",
      "product_id": "DEPOSIT_FORT_FIAT",
      "asset_type_id": "FIAT_TESTNET_USD"
    }
  }'
```

<ResponseField name="data" type="object">
  The newly created account object.
  <Expandable title="data fields">
    <ResponseField name="id" type="string">Account identifier (the value you provided).</ResponseField>
    <ResponseField name="customer_id" type="string">Owning customer's ID.</ResponseField>
    <ResponseField name="status" type="string">
      Account status. Starts as `PENDING_APPROVAL` until activated.
    </ResponseField>
    <ResponseField name="product_id" type="string">Product governing this account.</ResponseField>
    <ResponseField name="asset_type_id" type="string">Asset type held in this account.</ResponseField>
    <ResponseField name="current_balance" type="number">Current total balance (may include unsettled funds).</ResponseField>
    <ResponseField name="available_balance" type="number">Available balance for withdrawal or transfer.</ResponseField>
    <ResponseField name="created_at" type="string">ISO 8601 creation timestamp.</ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": {
    "id": "CUST001.USD.001",
    "customer_id": "CUST001",
    "status": "PENDING_APPROVAL",
    "product_id": "DEPOSIT_FORT_FIAT",
    "asset_type_id": "FIAT_TESTNET_USD",
    "current_balance": 0.00,
    "available_balance": 0.00,
    "created_at": "2024-01-16T10:00:00Z"
  }
}
```

## GET /v1/accounts/deposits

Returns a paginated list of all deposit accounts across your platform. Filter by customer or status to narrow results.

<ParamField query="customer_id" type="string">
  Return only accounts owned by this customer.
</ParamField>

<ParamField query="status" type="string">
  Filter by account status: `PENDING_APPROVAL`, `OPEN`, `SUSPENDED`, or `CLOSED`.
</ParamField>

<ParamField query="asset_type_id" type="string">
  Filter by asset type (e.g. `FIAT_USD`, `ETHEREUM_MAINNET_ETH`).
</ParamField>

<ParamField query="page" type="integer">
  Page number. Defaults to `1`.
</ParamField>

<ParamField query="page_size" type="integer">
  Results per page. Defaults to `20`, maximum `100`.
</ParamField>

```bash
curl -X GET "https://sandbox.layer2financial.com/api/v1/accounts/deposits?customer_id=CUST001&status=OPEN" \
  -H "Authorization: Bearer {AUTH_TOKEN}"
```

<ResponseField name="data" type="array">
  Array of account objects.
</ResponseField>

<ResponseField name="pagination" type="object">
  <Expandable title="pagination fields">
    <ResponseField name="total" type="integer">Total matching records.</ResponseField>
    <ResponseField name="page" type="integer">Current page.</ResponseField>
    <ResponseField name="page_size" type="integer">Records per page.</ResponseField>
    <ResponseField name="total_pages" type="integer">Total pages.</ResponseField>
  </Expandable>
</ResponseField>

```json
{
  "data": [
    {
      "id": "CUST001.USD.001",
      "customer_id": "CUST001",
      "status": "OPEN",
      "product_id": "DEPOSIT_FORT_FIAT",
      "asset_type_id": "FIAT_TESTNET_USD",

      "available_balance": 4500.00,

  "pagination": {
    "total": 1,
    "page": 1,
    "page_size": 20,
    "total_pages": 1
  }
}
```

## PATCH /v1/accounts/deposits/{id}

Updates the status of an existing account. Use this to suspend or reactivate an account as part of your compliance or customer lifecycle management.

<ParamField path="id" type="string" required>
  The unique account identifier.
</ParamField>

<ParamField body="status" type="string" required>
  The new status for the account. Allowed transitions: `OPEN` → `SUSPENDED`, `SUSPENDED` → `OPEN`, `OPEN` → `CLOSED`.
</ParamField>

<Warning>
  Closing an account (`CLOSED`) is irreversible. Ensure all funds have been withdrawn before closing. Attempting to close an account with a non-zero balance will return a `422 Unprocessable Entity` error.
</Warning>

```bash
curl -X PATCH https://sandbox.layer2financial.com/api/v1/accounts/deposits/CUST001.USD.001 \
  -H "Authorization: Bearer {AUTH_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "SUSPENDED"
  }'
```

```json
{
  "data": {
    "id": "CUST001.USD.001",
    "status": "SUSPENDED",
    "updated_at": "2024-01-21T09:00:00Z"
  }
}
```

## GET /v1/accounts/deposits/{id}/transactions

Returns a paginated list of all transactions on the account. Filter by type to view only deposits, withdrawals, transfers, or exchanges.

<ParamField path="id" type="string" required>
  The account identifier.
</ParamField>

<ParamField query="transaction_type" type="string">
  Filter by type: `DEPOSIT`, `WITHDRAWAL`, `TRANSFER`, or `EXCHANGE`.
</ParamField>

<ParamField query="status" type="string">
  Filter by transaction status (e.g. `COMPLETED`, `PENDING`, `FAILED`).
</ParamField>

<ParamField query="from_date" type="string">
  Return transactions on or after this ISO 8601 date (e.g. `2024-01-01T00:00:00Z`).
</ParamField>

<ParamField query="to_date" type="string">
  Return transactions on or before this ISO 8601 date.
</ParamField>

<ParamField query="page" type="integer">
  Page number. Defaults to `1`.
</ParamField>

<ParamField query="page_size" type="integer">
  Results per page. Defaults to `20`, maximum `100`.
</ParamField>

```bash
curl -X GET "https://sandbox.layer2financial.com/api/v1/accounts/deposits/CUST001.USD.001/transactions?transaction_type=DEPOSIT&status=COMPLETED" \
  -H "Authorization: Bearer {AUTH_TOKEN}"
```

<ResponseField name="data" type="array">
  Array of transaction objects.
  <Expandable title="transaction fields">
    <ResponseField name="id" type="string">Unique transaction identifier.</ResponseField>
    <ResponseField name="type" type="string">Transaction type: `DEPOSIT`, `WITHDRAWAL`, `TRANSFER`, or `EXCHANGE`.</ResponseField>
    <ResponseField name="amount" type="number">Transaction amount.</ResponseField>
    <ResponseField name="asset_type" type="string">Asset type of the transaction.</ResponseField>
    <ResponseField name="status" type="string">Current transaction status.</ResponseField>
    <ResponseField name="description" type="string">Optional description or memo.</ResponseField>
    <ResponseField name="created_at" type="string">ISO 8601 timestamp.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="pagination" type="object">

## GET /v1/accounts/deposits/{id}/deposit-instructions

Retrieves deposit instructions for the account. Depending on the account's product and asset type, instructions may include ACH routing details, Fedwire coordinates, SWIFT information, or a blockchain wallet address.

<ParamField path="id" type="string" required>
  The account identifier.
</ParamField>

<Tip>
  Share these instructions with your customers or payers to allow them to fund the account. For crypto accounts, provide the `address` field to the sender. For fiat accounts, provide the appropriate routing and account number for the desired network (ACH, FEDWIRE, or SWIFT).
</Tip>

```bash
curl -X GET https://sandbox.layer2financial.com/api/v1/accounts/deposits/CUST001.USD.001/deposit-instructions \
  -H "Authorization: Bearer {AUTH_TOKEN}"
```

<ResponseField name="data" type="object">
  Deposit instructions for this account. The structure varies by asset type.
  <Expandable title="fiat deposit instruction fields">
    <ResponseField name="account_id" type="string">The account these instructions belong to.</ResponseField>
    <ResponseField name="ach" type="object">
      ACH deposit details (fiat accounts only).
      <Expandable title="ACH fields">
        <ResponseField name="routing_number" type="string">ABA routing number.</ResponseField>
        <ResponseField name="account_number" type="string">Receiving account number.</ResponseField>
        <ResponseField name="account_type" type="string">e.g. `CHECKING`.</ResponseField>
        <ResponseField name="bank_name" type="string">Name of the receiving institution.</ResponseField>
        <ResponseField name="beneficiary_name" type="string">Account holder name.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="fedwire" type="object">
      Fedwire deposit details.
      <Expandable title="Fedwire fields">
        <ResponseField name="routing_number" type="string">Fedwire routing number.</ResponseField>
        <ResponseField name="account_number" type="string">Receiving account number.</ResponseField>
        <ResponseField name="bank_name" type="string">Receiving bank name.</ResponseField>
        <ResponseField name="beneficiary_name" type="string">Beneficiary name.</ResponseField>
        <ResponseField name="reference" type="string">Reference code to include with the wire.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="swift" type="object">
      SWIFT/international wire details.
      <Expandable title="SWIFT fields">
        <ResponseField name="swift_code" type="string">Bank SWIFT/BIC code.</ResponseField>
        <ResponseField name="account_number" type="string">IBAN or account number.</ResponseField>
        <ResponseField name="bank_name" type="string">Receiving bank name.</ResponseField>
        <ResponseField name="bank_address" type="string">Bank address.</ResponseField>
        <ResponseField name="beneficiary_name" type="string">Beneficiary name.</ResponseField>
        <ResponseField name="reference" type="string">Reference code.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="crypto_address" type="string">
      Blockchain address (digital-asset accounts only). Send funds to this address on the correct network.
    </ResponseField>
  </Expandable>
</ResponseField>
