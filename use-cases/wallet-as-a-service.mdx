Rail's Wallet as a Service (WaaS) lets you embed fully compliant digital currency wallets directly inside your product. Your customers can deposit, hold, transfer, withdraw, and exchange stablecoins and cryptocurrencies — all through a single unified API. Assets are custodied at multiple qualified custodians, so you inherit institutional-grade security without managing custody infrastructure yourself.

<Tip>
  Assets held in Rail wallets are custodied at multiple qualified custodians. You get institutional-grade security and regulatory compliance out of the box, with no custody infrastructure to manage on your end.
</Tip>

## Prerequisites

Before you start, make sure you have:

- A valid API token (see [Authentication](/get-started/authentication))
- A pre-onboarded customer with `ACTIVE` status (see [Customer Onboarding](/guides/customer-onboarding))
- Access to the Rail sandbox environment (see [Sandbox](/get-started/sandbox))

---

## Build guide

**Estimated time: 10 minutes**

<Steps>

  <Step title="Authenticate">
    All requests to the Rail API require a Bearer token in the `Authorization` header. Obtain your token from the Rail dashboard or your authentication flow, then include it with every request.

    ```bash
    Authorization: Bearer {AUTH_TOKEN}
    ```

    See [Authentication](/get-started/authentication) for full details on token management and expiry.
  </Step>

  <Step title="Open a crypto deposit account">
    Create a `DEPOSIT_FORT_CRYPTO` account for your customer. This account holds the customer's crypto balance and is linked to their `customer_id`. You define the `account_id` using a structured identifier that encodes the customer, asset, and account index.

    ```bash
    curl --request POST 'https://sandbox.layer2financial.com/api/v1/accounts/deposits' \
      --header 'Authorization: Bearer {AUTH_TOKEN}' \
      --header 'Content-Type: application/json' \
      --data '{
        "customer_id": "CUST001",
        "account_to_open": {
          "account_id": "CUST001.ETH.001",
          "product_id": "DEPOSIT_FORT_CRYPTO",
          "asset_type_id": "ETHEREUM_MAINNET_ETH"
        }
      }'
    ```

    Once created, the account starts in `PENDING_APPROVAL` status. Rail will move it to `OPEN` automatically once the account is ready. Subscribe to the `account.status.changed` webhook event to be notified when the account is ready to use (see [Webhooks Overview](/webhooks/overview)).
  </Step>

  <Step title="Generate a deposit address">
    Retrieve the on-chain deposit address for the account. Your customer sends crypto to this address to fund their wallet. Each account has a unique, persistent deposit address.

    ```bash
    curl --request GET 'https://sandbox.layer2financial.com/api/v1/accounts/deposits/CUST001.ETH.001/deposit-instructions' \
      --header 'Authorization: Bearer {AUTH_TOKEN}'
    ```

    The response includes the blockchain address, network details, and any memo or tag fields required for the asset. Share this address with your customer through your UI.

    <Note>
      In the sandbox environment, you can use Goerli testnet ETH to simulate deposits without spending real funds. See [Sandbox](/get-started/sandbox) for faucet details.
    </Note>
  </Step>

  <Step title="Receive a deposit">
    When your customer sends crypto to the deposit address, Rail detects the on-chain transaction and credits the account balance after the required number of confirmations. You do not need to poll — Rail fires an `account.deposit.completed` webhook event as soon as the deposit is confirmed.

    **Example webhook payload:**
    ```json
    {
      "id": "evt_abc123",
      "type": "account.deposit.completed",
      "created_at": "2024-01-15T10:30:00Z",
      "data": {
        "account_id": "CUST001.ETH.001",
        "amount": 1.5,
        "asset_type": "ETHEREUM_MAINNET_ETH",
        "transaction_id": "txn_xyz789"
      }
    }
    ```

    See [Webhook Events](/webhooks/events) for the full deposit event schema.
  </Step>

  <Step title="Transfer between accounts">
    Move funds between two accounts — for example, from a customer's ETH wallet to their USD account. Both accounts must be `OPEN` and belong to the same platform.

    ```bash
    curl --request POST 'https://sandbox.layer2financial.com/api/v1/transfers' \
      --header 'Authorization: Bearer {AUTH_TOKEN}' \
      --header 'Content-Type: application/json' \
      --data '{
        "source_account_id": "CUST001.ETH.001",
        "destination_account_id": "CUST001.USD.001",
        "amount": 0.5,
        "asset_type": "ETHEREUM_MAINNET_ETH"
      }'
    ```

    Rail fires a `transfer.completed` event once the transfer settles. See [Transfers & Exchanges](/guides/transfers-exchanges) for more on internal transfers.
  </Step>

  <Step title="Exchange crypto to fiat">
    Convert crypto to fiat (or between crypto assets) using Rail's built-in exchange. Specify the source and destination accounts, the amount to convert, and the asset types on each side.

    ```bash
    curl --request POST 'https://sandbox.layer2financial.com/api/v1/exchanges' \
      --header 'Authorization: Bearer {AUTH_TOKEN}' \
      --header 'Content-Type: application/json' \
      --data '{
        "source_account_id": "CUST001.ETH.001",
        "destination_account_id": "CUST001.USD.001",
        "source_amount": 1.0,
        "source_asset_type": "ETHEREUM_MAINNET_ETH",
        "destination_asset_type": "FIAT_USD"
      }'
    ```

    Rail applies the current market rate and settles both sides atomically. An `exchange.completed` webhook event is fired on success. See [Webhook Events](/webhooks/events) for the full exchange event schema.
  </Step>

</Steps>
