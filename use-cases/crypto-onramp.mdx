Rail's crypto on-ramp lets you accept fiat from your customers and deliver crypto to their wallets in a single, compliant flow. Whether you're building a crypto exchange, a neobank with crypto features, or a savings product backed by digital assets, Rail handles the fiat rails, compliance, and exchange execution so you can focus on your product experience.

## Prerequisites

Before you start, make sure you have:

- A valid API token (see [Authentication](/get-started/authentication))
- A customer with `ACTIVE` status and a verified fiat account (see [Customer Onboarding](/guides/customer-onboarding))
- Access to the Rail sandbox (see [Sandbox](/get-started/sandbox))

## On-ramp flow

<Steps>

  <Step title="Verify customer status">
    Before opening a crypto account, confirm that the customer has `ACTIVE` status and already holds an open fiat deposit account. The fiat account is the source of funds for the on-ramp exchange.

    You can check the customer's current status via the Customers API:

    ```bash
    curl --request GET 'https://sandbox.layer2financial.com/api/v1/customers/CUST001' \
      --header 'Authorization: Bearer {AUTH_TOKEN}'
    ```

    If the customer is not yet onboarded, complete the onboarding flow first. See [Customer Onboarding](/guides/customer-onboarding) for a step-by-step guide.
  </Step>

  <Step title="Open a crypto deposit account">
    Create a `DEPOSIT_FORT_CRYPTO` account for the customer. This account will receive the crypto after the exchange is executed.

    ```bash
    curl --request POST 'https://sandbox.layer2financial.com/api/v1/accounts/deposits' \
      --header 'Authorization: Bearer {AUTH_TOKEN}' \
      --header 'Content-Type: application/json' \
      --data '{
        "customer_id": "CUST001",
        "account_to_open": {
          "account_id": "CUST001.ETH.001",
          "product_id": "DEPOSIT_FORT_CRYPTO",
          "asset_type_id": "ETHEREUM_MAINNET_ETH"
        }
      }'
    ```

    Subscribe to the `account.status.changed` event to detect when the account moves to `OPEN` status before proceeding. See [Webhooks Overview](/webhooks/overview).

    <Note>
      You can open crypto accounts for multiple asset types (e.g., BTC, USDC) by changing the `asset_type_id`. See [Assets](/concepts/assets) for a full list of supported asset types.
    </Note>
  </Step>

  <Step title="Fund the fiat account">
    Instruct your customer to deposit fiat into their existing fiat account. Rail supports standard deposit methods including ACH and wire transfers. Retrieve the deposit instructions for the fiat account:

    ```bash
    curl --request GET 'https://sandbox.layer2financial.com/api/v1/accounts/deposits/CUST001.USD.001/deposit-instructions' \
      --header 'Authorization: Bearer {AUTH_TOKEN}'
    ```

    The response includes routing numbers, account numbers, and any reference codes the customer should include with their transfer.

    Rail fires an `account.deposit.completed` webhook event when the fiat deposit is confirmed. Use this event to trigger the next step automatically, rather than polling the account balance.
  </Step>

  <Step title="Execute the fiat-to-crypto exchange">
    Once fiat is available in the source account, execute an exchange to convert it into crypto. Specify the fiat source account, the crypto destination account, the amount to convert, and the asset types.

    ```bash
    curl --request POST 'https://sandbox.layer2financial.com/api/v1/exchanges' \
      --header 'Authorization: Bearer {AUTH_TOKEN}' \
      --header 'Content-Type: application/json' \
      --data '{
        "source_account_id": "CUST001.USD.001",
        "destination_account_id": "CUST001.ETH.001",
        "source_amount": 500.00,
        "source_asset_type": "FIAT_USD",
        "destination_asset_type": "ETHEREUM_MAINNET_ETH"
      }'
    ```

    Rail applies the current market rate and atomically debits the fiat account and credits the crypto account. An `exchange.completed` event is fired on success.

    <Warning>
      Exchange rates are live. Always confirm the quoted rate with your customer before executing the exchange if your product requires rate transparency or a confirmation step.
    </Warning>
  </Step>

  <Step title="(Optional) Withdraw crypto to an external wallet">
    If your product allows customers to move crypto off-platform, you can initiate a withdrawal to an external blockchain address once the exchange settles.

    ```bash
    curl --request POST 'https://sandbox.layer2financial.com/api/v1/withdrawals' \
      --header 'Authorization: Bearer {AUTH_TOKEN}' \
      --header 'Content-Type: application/json' \
      --data '{
        "source_account_id": "CUST001.ETH.001",
        "destination_address": "0xRecipientAddress",
        "amount": 0.25,
        "asset_type": "ETHEREUM_MAINNET_ETH"
      }'
    ```

    Rail fires `withdrawal.status.changed` and `withdrawal.completed` events as the transaction progresses on-chain. See [Withdrawals](/guides/withdrawals) for full details.
  </Step>

</Steps>

## Key events to handle

| Event | When it fires |
|---|---|
| `account.status.changed` | Crypto account moves to `OPEN` — safe to proceed |
| `account.deposit.completed` | Fiat deposit confirmed — trigger the exchange |
| `exchange.completed` | Exchange settled — crypto available in wallet |
| `exchange.failed` | Exchange failed — notify customer and retry |
| `withdrawal.completed` | Crypto sent to external wallet |

See [Webhook Events](/webhooks/events) for the full event reference and payload schemas.
