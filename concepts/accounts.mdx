An **Account** is a balance container tied to a single asset type. When a customer wants to hold USD, ETH, or any other supported asset, you create a dedicated account for that asset. A single customer can have multiple accounts across different asset classes — for example, one account for fiat USD and another for Ethereum. All deposits, withdrawals, transfers, exchanges, and payments are routed through accounts, so understanding account setup and lifecycle is essential before initiating any money movement.

## Account Product Types

Every account is created with a `product_id` that determines whether it holds fiat or crypto assets and how custody is managed.

<CardGroup cols={2}>
  <Card title="DEPOSIT_FORT_FIAT" icon="building-columns">
    A fiat deposit account for currencies such as USD. Supports ACH, FEDWIRE, and SWIFT inflows and outflows.
  </Card>
  <Card title="DEPOSIT_FORT_CRYPTO" icon="bitcoin-sign">
    A crypto deposit account for digital assets such as ETH, BTC, USDC, and USDT. Holds on-chain assets with a dedicated deposit address.
  </Card>
</CardGroup>

## Asset Type IDs

Every account is tied to exactly one asset, identified by an `asset_type_id` string. The format is:

```
{BLOCKCHAIN}_{NETWORK}_{CURRENCY_CODE}
```

For fiat assets, the blockchain segment is replaced with `FIAT`:

```
FIAT_{NETWORK}_{CURRENCY_CODE}
```

<Tabs>
  <Tab title="Production">
    | Asset | asset_type_id |
    |---|---|
    | US Dollar | `FIAT_USD` |
    | Ethereum | `ETHEREUM_MAINNET_ETH` |
    | Bitcoin | `BITCOIN_MAINNET_BTC` |
    | USD Coin | `ETHEREUM_MAINNET_USDC` |
    | Tether | `ETHEREUM_MAINNET_USDT` |
  </Tab>
  <Tab title="Sandbox">
    | Asset | asset_type_id |
    |---|---|
    | US Dollar (test) | `FIAT_TESTNET_USD` |
    | Ethereum (Goerli) | `ETHEREUM_GOERLI_ETH` |

    <Note>
      In the sandbox, always use `TESTNET` or a named test network (e.g., `GOERLI`) in the `asset_type_id`. Production IDs will be rejected in the sandbox environment.
    </Note>
  </Tab>
</Tabs>

See [Supported Assets](/concepts/assets) for the full list of asset IDs and details on custody.

## Account Lifecycle

Accounts move through a defined set of states from creation to closure.

```
  POST /v1/accounts/deposits
           │
           ▼
        PENDING  ──► (Rail activates after setup)
           │
           ▼
          OPEN   ──────────────────────────────┐
           │                                   │
           ▼                                   ▼
       SUSPENDED                            CLOSED
    (temporary hold)               (permanent deactivation)
```

| Status | Description |
|---|---|
| `PENDING` | Account has been created but is not yet ready to receive funds |
| `OPEN` | Account is active; deposits, withdrawals, and transfers are permitted |
| `SUSPENDED` | Account is temporarily restricted; no new transactions allowed |
| `CLOSED` | Account has been permanently deactivated |

<Warning>
  Attempting to initiate a deposit or withdrawal on an account that is not in `OPEN` status will result in a `422 Unprocessable Entity` error. Always check account status before initiating transactions.
</Warning>

## Key Fields

<ResponseField name="id" type="string" required>
  The account identifier. This can be a Rail-generated ID or an **external identifier from your own system**, giving you control over ID management across platforms.
</ResponseField>

<ResponseField name="customer_id" type="string" required>
  The ID of the customer who owns this account.
</ResponseField>

<ResponseField name="product_id" type="string" required>
  The account product type: `DEPOSIT_FORT_FIAT` or `DEPOSIT_FORT_CRYPTO`.
</ResponseField>

<ResponseField name="asset_type_id" type="string" required>
  The asset this account holds, e.g. `FIAT_USD` or `ETHEREUM_MAINNET_ETH`.
</ResponseField>

<ResponseField name="status" type="string" required>
  Current lifecycle state: `PENDING`, `OPEN`, `SUSPENDED`, or `CLOSED`.
</ResponseField>

<ResponseField name="current_balance" type="string">
  The total balance in the account, including any funds that are pending settlement. Represented as a decimal string.
</ResponseField>

<ResponseField name="available_balance" type="string">
  The portion of the balance that is immediately available for withdrawal or transfer. This excludes pending or reserved amounts.
</ResponseField>

## Creating an Account

Use `POST /v1/accounts/deposits` to open a new deposit account for a customer. You must provide the `customer_id` (obtained after onboarding), the `product_id`, and the `asset_type_id`.

<CodeGroup>
  ```bash cURL
  curl --request POST \
    --url https://sandbox.layer2financial.com/api/v1/accounts/deposits \
    --header 'Authorization: Bearer YOUR_API_KEY' \
    --header 'Content-Type: application/json' \
    --data '{
      "id": "acct_usd_alice_001",
      "customer_id": "cust_01hq7z3xkfbp9rn2vwme4d5j6c",
      "product_id": "DEPOSIT_FORT_FIAT",
      "asset_type_id": "FIAT_TESTNET_USD"
    }'
  ```

  ```javascript Node.js
  const response = await fetch(
    'https://sandbox.layer2financial.com/api/v1/accounts/deposits',
    {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${process.env.RAIL_API_KEY}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        id: 'acct_usd_alice_001',
        customer_id: 'cust_01hq7z3xkfbp9rn2vwme4d5j6c',
        product_id: 'DEPOSIT_FORT_FIAT',
        asset_type_id: 'FIAT_TESTNET_USD',
      }),
    }
  );

  const account = await response.json();
  console.log(account.id, account.status);
  ```

  ```python Python
  import requests

  response = requests.post(
      "https://sandbox.layer2financial.com/api/v1/accounts/deposits",
      headers={
          "Authorization": f"Bearer {api_key}",
          "Content-Type": "application/json",
      },
      json={
          "id": "acct_usd_alice_001",
          "customer_id": "cust_01hq7z3xkfbp9rn2vwme4d5j6c",
          "product_id": "DEPOSIT_FORT_FIAT",
          "asset_type_id": "FIAT_TESTNET_USD",
      },
  )

  account = response.json()
  print(account["id"], account["status"])
  ```
</CodeGroup>

**Example response:**

```json
{
  "id": "acct_usd_alice_001",
  "customer_id": "cust_01hq7z3xkfbp9rn2vwme4d5j6c",
  "product_id": "DEPOSIT_FORT_FIAT",
  "asset_type_id": "FIAT_TESTNET_USD",
  "status": "PENDING",
  "current_balance": "0.00",
  "available_balance": "0.00",
  "created_at": "2024-03-15T11:05:00Z",
  "updated_at": "2024-03-15T11:05:00Z"
}
```

## Retrieving an Account

Once an account has been created, retrieve it at any time to check its status and current balance.

<CodeGroup>
  ```bash cURL
  curl --request GET \
    --url https://sandbox.layer2financial.com/api/v1/accounts/deposits/acct_usd_alice_001 \
    --header 'Authorization: Bearer YOUR_API_KEY'
  ```

  ```javascript Node.js
  const response = await fetch(
    'https://sandbox.layer2financial.com/api/v1/accounts/deposits/acct_usd_alice_001',
    {
      method: 'GET',
      headers: {
        'Authorization': `Bearer ${process.env.RAIL_API_KEY}`,
      },
    }
  );

  const account = await response.json();
  ```

  ```python Python
  import requests

  response = requests.get(
      "https://sandbox.layer2financial.com/api/v1/accounts/deposits/acct_usd_alice_001",
      headers={"Authorization": f"Bearer {api_key}"},
  )

  account = response.json()
  ```
</CodeGroup>

**Example response:**

```json
{
  "id": "acct_usd_alice_001",
  "customer_id": "cust_01hq7z3xkfbp9rn2vwme4d5j6c",
  "product_id": "DEPOSIT_FORT_FIAT",
  "asset_type_id": "FIAT_TESTNET_USD",
  "status": "OPEN",
  "current_balance": "1500.00",
  "available_balance": "1250.00",
  "created_at": "2024-03-15T11:05:00Z",
  "updated_at": "2024-03-15T12:30:00Z"
}
```

<Tip>
  The difference between `current_balance` and `available_balance` represents funds that are in-flight (e.g., a pending withdrawal that has been initiated but not yet settled). Use `available_balance` when deciding whether a customer has sufficient funds for a new transaction.
</Tip>
