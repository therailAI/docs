A **Customer** is the central entity in Rail. Every account, counterparty, and transaction on the platform belongs to a customer, making the `customer_id` the most important identifier you will work with. Customers are never created directly through the API — they are always the result of a completed and approved **Application** (the KYC/KYB onboarding flow). Once a Customer exists, you use that record to open accounts, register counterparties, and initiate money movement.

## Customer Types

Rail supports two customer types, which determine the onboarding requirements and the compliance checks applied.

<CardGroup cols={2}>
  <Card title="INDIVIDUAL" icon="person">
    A natural person. Requires personal identity verification (KYC), including government-issued ID, date of birth, and address. The onboarding Application spans **6 steps**.
  </Card>
  <Card title="CORPORATION" icon="building">
    A legal business entity. Requires KYB documentation including articles of incorporation, EIN, and details about the business. Corporate applications span **7 steps** and include adding beneficial owners — each of whom is onboarded as an individual.
  </Card>
</CardGroup>

## Customer Lifecycle

Customers move through a defined set of statuses as the Application progresses through review.

```
Application INCOMPLETE
       │
       ▼
Application READY_FOR_SUBMISSION
       │
       ▼
Application SUBMITTED  ◄──── CHANGES_REQUESTED (if KYC needs more info)
       │
       ▼
Application APPROVED
       │
       ▼
  Customer ACTIVE
```

<Note>
  If an Application enters **CHANGES_REQUESTED**, you must supply the additional information or documents and re-submit before the review can continue. See [Customer Onboarding](/guides/customer-onboarding) for the step-by-step process.
</Note>

Once a Customer record is created, its status reflects operational health:

| Status | Meaning |
|---|---|
| `ACTIVE` | Customer is in good standing; all operations permitted |
| `SUSPENDED` | Temporarily restricted; no new transactions allowed |
| `CLOSED` | Customer record is permanently deactivated |

## Key Fields

<ResponseField name="customer_id" type="string" required>
  The unique Rail-assigned identifier for this customer. Use this ID in all subsequent API calls — account creation, counterparty registration, and transaction initiation all require it.
</ResponseField>

<ResponseField name="type" type="string" required>
  Either `INDIVIDUAL` or `CORPORATION`. Set during the Application and immutable afterwards.
</ResponseField>

<ResponseField name="status" type="string" required>
  Current operational status: `ACTIVE`, `SUSPENDED`, or `CLOSED`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the Customer record was created (i.e., when the Application was approved).
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the most recent status change or profile update.
</ResponseField>

## Retrieving a Customer

After an Application is approved, you can fetch the full Customer record at any time using the `customer_id`.

<CodeGroup>
  ```bash cURL
  curl --request GET \
    --url https://sandbox.layer2financial.com/api/v1/customers/{customer_id} \
    --header 'Authorization: Bearer YOUR_API_KEY'
  ```

  ```javascript Node.js
  const response = await fetch(
    `https://sandbox.layer2financial.com/api/v1/customers/${customerId}`,
    {
      method: 'GET',
      headers: {
        'Authorization': `Bearer ${process.env.RAIL_API_KEY}`,
        'Content-Type': 'application/json',
      },
    }
  );

  const customer = await response.json();
  console.log(customer.customer_id, customer.status);
  ```

  ```python Python
  import requests

  response = requests.get(
      f"https://sandbox.layer2financial.com/api/v1/customers/{customer_id}",
      headers={"Authorization": f"Bearer {api_key}"},
  )

  customer = response.json()
  print(customer["customer_id"], customer["status"])
  ```
</CodeGroup>

**Example response:**

```json
{
  "customer_id": "cust_01hq7z3xkfbp9rn2vwme4d5j6c",
  "type": "INDIVIDUAL",
  "status": "ACTIVE",
  "created_at": "2024-03-15T10:22:31Z",
  "updated_at": "2024-03-15T10:22:31Z"
}
```

<Tip>
  Store the `customer_id` in your own database immediately after a Customer is created. You will need it to open accounts, add counterparties, and look up transaction history.
</Tip>

## Using the Customer ID

The `customer_id` appears as a required parameter across nearly every Rail API resource:

- **Accounts** — pass `customer_id` when creating a new deposit account
- **Counterparties** — scope each counterparty to a specific customer
- **Deposits / Withdrawals / Transfers** — all transactions are linked to the customer via their account
