Rail supports a range of fiat currencies and digital assets, each identified by a structured `asset_type_id` string. Understanding the asset identifier format is important because you will use it every time you open an account, look up supported assets, or interpret transaction records. Assets are held in custody by qualified financial institutions, ensuring regulatory compliance and fund security for both you and your customers.

## Asset ID Format

The `asset_type_id` follows a consistent three-part convention:

```text
{BLOCKCHAIN}_{NETWORK}_{CURRENCY_CODE}
```

Each segment serves a specific purpose:

| Segment | Description | Example |
|---|---|---|
| `BLOCKCHAIN` | The underlying chain or asset class | `ETHEREUM`, `BITCOIN`, `FIAT` |
| `NETWORK` | The network environment | `MAINNET`, `TESTNET`, `GOERLI` |
| `CURRENCY_CODE` | The ISO currency code or token symbol | `ETH`, `BTC`, `USD`, `USDC` |

For fiat assets, the `BLOCKCHAIN` segment is replaced with `FIAT`, since no blockchain applies. In the production environment the network segment is omitted, while sandbox IDs include an explicit network segment:

```text
FIAT_{CURRENCY_CODE}          # Production fiat
FIAT_{NETWORK}_{CURRENCY_CODE} # Sandbox / testnet fiat

# Examples
FIAT_USD           # Production US Dollar
FIAT_TESTNET_USD   # Sandbox US Dollar (testnet)
```

<Note>
  The presence of the `NETWORK` segment distinguishes sandbox asset IDs from production ones. Always use `TESTNET` (or a named test network such as `GOERLI`) in the sandbox environment. Production asset IDs are rejected in sandbox, and vice versa.
</Note>

## Production vs. Sandbox Asset IDs

It is easy to mix up production and sandbox identifiers. The table below shows side-by-side equivalents for the most common assets:

| Asset | Production ID | Sandbox ID |
|---|---|---|
| US Dollar | `FIAT_USD` | `FIAT_TESTNET_USD` |
| Ethereum | `ETHEREUM_MAINNET_ETH` | `ETHEREUM_GOERLI_ETH` |

<Warning>
  Using a production `asset_type_id` (e.g., `FIAT_USD`) in a sandbox API call will result in a validation error. Ensure your environment configuration maps asset IDs correctly before switching between sandbox and production.
</Warning>

## Asset Custody

Rail does not self-custody your customers' funds. All assets — fiat and digital — are held at **qualified custodians**: regulated banks, trust companies, and licensed digital asset custodians.

Key points:

- **Fiat assets** are held at FDIC-member institutions or regulated trust companies.
- **Crypto assets** are custodied at licensed digital asset custodians with institutional-grade security, insurance coverage, and segregated account structures.
- Custodian assignments are managed by Rail and may span multiple institutions for redundancy and regulatory compliance.
- You do not interact with custodians directly — all custody operations are abstracted through the Rail API.

<Note>
  Specific custodian relationships are disclosed as part of your platform agreement. Contact your Rail account manager if you need custodian documentation for your own compliance program.
</Note>

## Using Asset IDs in API Calls

You reference `asset_type_id` when creating accounts and when interpreting balances and transaction records. Here is an example showing the `asset_type_id` in context:

```json
{
  "id": "acct_eth_bob_001",
  "customer_id": "cust_01hq7z3xkfbp9rn2vwme4d5j6c",
  "product_id": "DEPOSIT_FORT_CRYPTO",
  "asset_type_id": "ETHEREUM_MAINNET_ETH",
  "status": "OPEN",
  "current_balance": "2.450000000000000000",
  "available_balance": "2.450000000000000000"
}
```

<Tip>
  Crypto balances are represented as decimal strings with full precision for the asset's native decimal places (18 decimal places for ETH). Always treat balance values as strings rather than floating-point numbers to avoid precision loss.
</Tip>
