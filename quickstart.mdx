title: "Make your first Rail call"
description: "Check your identity and project access in a provisioned Rail environment."
---

This quickstart makes a read-only API call. You need `curl`, an operator-provided Rail endpoint, and an OAuth access token with `platform:read`. You do not need payment credentials.

## 1. Get an environment

Ask your Rail operator for the customer API base URL, identity-provider configuration, tenant enrollment, project access, and supported contract version. See [environment setup](/get-started/environment).

There is no shared public sandbox URL or self-service API-key flow established in this documentation. Hosts ending in `.invalid` in the downloadable contract are placeholders.

## 2. Set your connection

Set `RAIL_BASE_URL` to your provisioned HTTPS endpoint without a trailing slash or `/v1` suffix. Supply `RAIL_ACCESS_TOKEN` through your secret manager or local environment. Do not put either value in committed examples.

```bash
: "${RAIL_BASE_URL:?Set your provisioned Rail customer API base URL}"
: "${RAIL_ACCESS_TOKEN:?Supply an OAuth access token}"

curl --fail-with-body --silent --show-error \
  "${RAIL_BASE_URL%/}/v1/context" \
  --header "Authorization: Bearer ${RAIL_ACCESS_TOKEN}" \
  --header 'Accept: application/json'
```

Do not add a tenant-selection header. Rail derives the tenant and principal from the authenticated identity and enrollment.

## 3. Check the context

The response identifies `tenant_id`, `principal_id`, `oauth_subject`, `scopes`, `project_ids`, and `api_version`. Check that the identity and projects match your intended integration. A token with the right scope can still lack access to a referenced object.

```json
{
  "tenant_id": "ten_example0001",
  "principal_id": "pri_example0001",
  "oauth_subject": "example-workload",
  "scopes": ["platform:read"],
  "project_ids": ["prj_example0001"],
  "api_version": "v1"
}
```

These IDs are illustrative; your environment returns its own values.
