## Install

<Tabs>
  <Tab title="macOS and Linux (Homebrew)">
    ```bash
    brew install therailai/tap/rail
    ```
  </Tab>
  <Tab title="Binary download">
    Download the archive for your operating system and architecture (macOS, Linux and Windows; amd64 and arm64) from [Rail CLI releases](https://github.com/therailAI/rail-cli-releases/releases). Check it against the release's `checksums.txt`, then put `rail` on your `PATH`.
  </Tab>
</Tabs>

```bash
rail version          # CLI, API contract and release manifest; -json for scripts
```

Offline bundle verification needs only the binary, a bundle, and a trust anchor; it works without a profile. See [export and verify](/cli/evidence).

## Commands

| Command | Purpose |
| --- | --- |
| `rail init` | Write a project's `rail.yaml` and an example effect |
| `rail sandbox up`, `down`, `reset`, `status`, `logs`, `token`, `ca`, `trust`, `untrust` | Run and manage the [local sandbox](/get-started/sandbox) |
| `rail login`, `rail whoami`, `rail logout` | Select and inspect a profile |
| `rail govern`, `rail govern resume` | Run an effect through authorization and dispatch |
| `rail grants`, `rail delegations`, `rail tokens` | Manage bounded authority |
| `rail executions`, `rail approvals` | Inspect state and vote as an enrolled approver |
| `rail receipts`, `rail policy` | Inspect evidence and policy pins |
| `rail journey export` | Export a grant journey's evidence and verify it |
| `rail bundle inspect`, `rail verify` | Inspect and verify bundles offline |
| `rail mcp serve` | Run the [MCP proxy](https://www.npmjs.com/package/@therailai/mcp) for a host |
| `rail dev` | Run the stack from a source workspace |

What a command may do depends on the profile's roles. A successful login does not grant authority to perform a protected action.
