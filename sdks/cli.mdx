The CLI on the repository `main` branch covers the full developer workflow: project initialization, local provisioning, shared profiles, governed shell commands, approvals, journey export, offline verification, and the [MCP proxy](/sdks/mcp-proxy). Earlier builds had only offline verification and operator demo tooling; check your build with `rail version` and [implementation and release status](/get-started/implementation-status).

## Get the CLI

Build the CLI from the `rail-go` repository source, or obtain a versioned binary for your operating system and architecture from your Rail operator. There is no public binary release or universal installer yet.

```bash
rail version
```

Offline bundle verification needs the binary, a supported bundle, and a confirmed trust anchor. It works without a profile. See [offline verification](/cli/evidence).

## Command availability

| Command | Purpose |
| --- | --- |
| `rail bundle inspect`, `rail verify` | Inspect and verify supported bundles offline |
| `rail init`, `rail dev` | Initialize and provision a project |
| `rail login`, `rail whoami`, `rail logout` | Select and inspect a profile |
| `rail govern`, `rail govern resume` | Run an effect through authorization and dispatch gates |
| `rail grants`, `rail delegations`, `rail tokens` | Manage bounded authority |
| `rail executions`, `rail approvals` | Inspect state and vote as an enrolled approver |
| `rail receipts`, `rail policy` | Inspect evidence and policy pins |
| `rail journey export` | Export a grant journey's evidence |
| `rail mcp serve` | Run the governing [MCP proxy](/sdks/mcp-proxy) in front of an MCP server |

Command availability depends on your build; access depends on the profile's roles. A successful login does not grant authority to perform a protected action.
