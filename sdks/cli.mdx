Use `rail` to work through the execution lifecycle from your terminal. The development CLI supports local provisioning, shared identity profiles, governed shell commands, approvals, and evidence verification.

## Get the CLI

Obtain a versioned binary for your operating system and architecture, or a matching source workspace and build instructions, from your Rail operator. A public binary release or universal installer is not established by these docs.

```bash
rail version
```

Offline bundle verification needs the binary, a supported bundle, and a confirmed trust anchor. Connected commands also need a provisioned environment and profile. `rail dev up` requires the full supplied development workspace; the binary alone does not contain the services.

## Command families

| Command | Purpose |
| --- | --- |
| `rail init`, `rail dev` | Create a project specification and manage the development stack |
| `rail login`, `rail whoami`, `rail logout` | Select and inspect a profile |
| `rail govern`, `rail govern resume` | Run an effect through authorization and dispatch gates |
| `rail grants`, `rail delegations`, `rail tokens` | Work with bounded authority and capability tokens |
| `rail executions`, `rail approvals` | Inspect execution state and act through an enrolled approver |
| `rail receipts`, `rail policy` | Inspect evidence and policy pins |
| `rail journey export` | Export connected evidence for a grant journey |
| `rail bundle inspect`, `rail verify` | Inspect and verify supported bundles offline |

Command availability and access depend on the supplied version and the profile's roles. A successful login does not grant authority to perform a protected action.
