## Install from a supplied checkout

This page covers repository SDK `0.1.0.dev0`. The governed helper and generic-call custom-header argument require the separately supplied `0.2.0.dev0` build described in [the local preview guide](/sdks/governed-python). See [implementation status](/get-started/implementation-status).

Use Python 3.12+ and a matching source checkout supplied by your operator. Replace the path with the checkout you received:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install /path/to/rail-sdk-python
```

This is a source-install workflow; public PyPI publication is not established here.

## Read your context

```python
import os
from rail_sdk import RailClient, RailError

client = RailClient(
    os.environ["RAIL_BASE_URL"],
    lambda: os.environ["RAIL_ACCESS_TOKEN"],
)
try:
    data, headers = client.call("getContext")
    print(data["principal_id"], data["project_ids"])
except RailError as error:
    print("Rail HTTP status:", error.status)
    raise
finally:
    client.close()
```

For a long-running process, use a token callback that refreshes credentials through your configured identity provider. The static environment-token example is a minimal connection check.

For this context call, `RAIL_BASE_URL` must route to the platform service. The next example uses `RAIL_EXECUTION_BASE_URL` for the execution service. Both may be the same only when your operator provides a gateway covering both. Product methods do not select a different service address automatically.

## Product methods and options

```python
import os
from rail_sdk import RailClient

client = RailClient(
    os.environ["RAIL_EXECUTION_BASE_URL"],
    lambda: os.environ["RAIL_ACCESS_TOKEN"],
)
try:
    data, headers = client.execution.get_execution(
        path={"execution_id": os.environ["RAIL_EXECUTION_ID"]}
    )
    print(data["state"], data["external_effect"])
    etag = headers.get("etag")
finally:
    client.close()
```

Mutations require `idempotency_key`. Pass the latest strong ETag in `if_match` when required. Repository SDK `0.1.0.dev0` accepts no per-call `headers` argument on either the generic call or product methods. For a capability-bound request, supply a dedicated operator-qualified `httpx.Client` carrying that operation's capability and certificate-bound transport, use direct authenticated HTTP, or obtain the `0.2.0.dev0` preview that adds generic-call custom headers. Do not attach a capability globally to a client reused across unrelated operations.

If you supply an `httpx.Client`, you retain responsibility for its lifecycle. The Rail client closes only a transport it created itself.

Requests and successful responses are schema-checked. There are no automatic mutation retries. Preserve operation identity and [reconcile uncertain effects](/guides/recovery).
