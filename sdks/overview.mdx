## Two SDK layers

Use `RailClient` for customer API calls. In the separately supplied local preview, `Rail.fromProfile` in TypeScript or `Rail.from_profile` in Python coordinates a protected effect through an enrolled worker. Those helper imports are absent from the reviewed repository default branches and require runtime configuration and role-specific credentials beyond the customer HTTP API.

Start a governed call with the [TypeScript example](/sdks/governed-typescript) or [Python example](/sdks/governed-python).

## Customer API namespaces

The TypeScript and Python clients expose the same customer operation catalog. Product namespaces group operations without changing request schemas, response schemas, or authority requirements.

| Namespace | Product |
| --- | --- |
| `execution` | Governed Execution |
| `authority` | Agent Authority |
| `evidence` | Evidence & Verification |
| `assets` | Assets & Lifecycle |
| `lineage` | Lineage & Rights |
| `settlement` | Settlement |

Shared and advanced operations are available through the generic `call` method. TypeScript uses camelCase operation names; Python product methods use snake_case. The generic Python `call` accepts the contract's camelCase operation ID.

## Distribution status

The reviewed repository versions are TypeScript `0.1.0-dev.0` and Python `0.1.0.dev0`, against customer contract 0.1.1. The explicitly marked local-preview guides use TypeScript `0.2.0-dev.0`, Python `0.2.0.dev0`, and the matching newer CLI. These are different source baselines, not interchangeable releases.

The TypeScript package is private, and the repository version's export map blocks a normal package import. Follow the [source-build instructions](/sdks/typescript). Obtain versioned source or a qualified distribution from your operator; do not assume `npm install @rail/sdk` or `pip install rail-sdk` resolves to a supported public release.

The examples use Node.js 22 or Python 3.12+, respectively. Supply environment credentials separately.

## Client behavior

Both clients validate request and successful-response shape and require explicit idempotency keys for mutations. They perform one request without automatic mutation retries. They return data and response metadata; the metadata is useful for ETags and asynchronous resource locations.

A client uses one configured base URL. Product namespaces organize methods but do not route to different services. Use service-specific clients, or an operator-supplied gateway that covers the requested paths.
