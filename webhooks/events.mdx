---
title: "Event feed and event types"
description: "Read the durable feed and recover notification delivery."
---

Use [`listEvents`](/api-reference/endpoints/list-events) to read authorized events. The envelope uses CloudEvents 1.0 structured JSON with Rail tenant, project, and sequence extensions.

Events notify you that a resource changed. They do not carry permission to execute, release a result, or pay. Re-fetch the referenced resource under current authorization.

## Feed recovery

Persist the last successfully processed event position. Use an opaque cursor or `after_event_id` as documented, never both. The contract describes a 30-day feed/manual replay horizon; confirm retention in your environment. Expired positions produce a typed error rather than silently restarting history.

Do not rely on webhook arrival order. A timestamp or stream-local sequence does not create a global causal order across services.

## Useful notification families

Execution changes, approval requests, committed receipts, projection changes, authority revocation, settlement changes, and edge reconciliation each have event types in the contract. Use the declared type values from the API schema when creating subscriptions.

## Replay a delivery

Use [`replayWebhookDelivery`](/api-reference/endpoints/replay-webhook-delivery) for an existing delivery when authorized. Preserve event deduplication in your receiver. Replaying a notification never creates a new execution or transfer.

For exact signature handling, see [webhooks](/webhooks/overview).
