## Two ways to run against the Rail

- **The local sandbox.** One command starts the complete Rail on your machine, with development identities and simulated effects. Use it to learn the API, build an integration, and run tests. See [the local sandbox](/get-started/sandbox) and the [quickstart](/quickstart).
- **An operator environment.** A Rail deployment your operator runs and qualifies, with your identity provider, real targets, and production controls. The rest of this page covers what to request.

| Surface | Status |

| Customer OpenAPI | Contract 0.1.1, 127 operations |
| Developer tools | Release 0.2.0: CLI, local sandbox, TypeScript and Python SDKs, MCP proxy. See [implementation and release status](/get-started/implementation-status) |

| Recorded workflows | Reference runs with explicit test, stub, fixture, or synthetic inputs |
| Hosted API endpoint | Provided and qualified per deployment |
| Production readiness | Must be established for your environment and workflow |

The product catalog groups the customer contract into six products. Grouping an operation does not establish that it is enabled at your gateway or entitled for your project.

## Request these connection details

For an operator environment, import the profile descriptor your operator supplies with [`rail login`](/cli/profiles).

- Service-specific API base URLs and supported contract version, or a confirmed gateway routing all required operations.
- Identity provider, token endpoint, expected audience, and allowed grants.
- Enrolled principal, tenant, project membership, and least-privilege scopes.
- Published action definitions, schemas, policies, bindings, and target configuration.
- Authority grants and any capability or sender-binding requirements.
- Supported adapter behavior, effect idempotency, recovery, and settlement integration.

Use separate identities for workloads, human approvers, runtime workers, and verification responsibilities. Your deployment operator controls those boundaries.

## Before a production integration

Qualify the complete protected execution path. Confirm how the adapter detects duplicate effects, reports uncertainty, and reconciles provider outcomes. Test revoked authority, expired evidence, changed versions, approval races, lost acknowledgements, and uncertain external effects.

Agree on identity lifecycle, signing-key rotation, retention, monitoring, availability, and recovery requirements. The reference demonstrations do not provide a service-level commitment or performance result for your workload.
